NL-I44: Reason Hint Extraction Resolves Annotations on the EDT — "Slow operations are prohibited on EDT" Errors

Resolvedon version 1.0.0

Found on version 1.0.0 by Kurv Cygnus

Description

In a real project, the IDE log gets flooded with Slow operations are prohibited on EDT errors (plus a Should be called at least in the state COMPONENTS_LOADED cascade) while Nullify reason hints (NL-F16) are shown above collapsed folds. The violations point into Nullify's hint code — the fold's reason is being resolved with index access on the UI thread.

Root Cause

Every collapsed fold re-reads its annotation's reason on the UI thread after each folding pass, and reading an annotation's fully qualified name forces the IDE to resolve the annotation class through the project index — which the platform forbids on the UI thread. The hint code assumed this resolution was index-free, but annotation names are class-name references and cannot be qualified without resolving them.

Solution Result

The reason extraction behind a collapsed fold's hint now runs on a background thread, so writing or folding nullability annotations no longer performs index resolution on the UI thread — the Slow operations are prohibited on EDT errors are gone.

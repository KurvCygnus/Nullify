NL-F22: AppendNullabilityDocIntention — Nullability Javadoc Sentences for Undocumented Elements

Completedon version 1.0.0

Suggested on version 1.0.0 by Kurv Cygnus

Description

A nullability annotation (@Nullable, @NotNull, …) tells the compiler and the linter how a value behaves, but the people reading the code often learn it from the Javadoc instead: @param key a String which is nullable because it is absent for anonymous users. Writing that sentence by hand is tedious — the annotation already carries the nullability mark, so the sentence is almost fully derivable. Still, it is exactly the kind of documentation that readers expect and that code generators and IDEs surface.

AppendNullabilityDocIntention closes the gap on Alt+Enter. It fires when both conditions hold:

  1. the target element carries a registered nullability annotation (built-in or user-registered — custom annotation libraries participate);

  2. the element's Javadoc does not document it yet — a method parameter without its @param tag, a return type without @return, a thrown type without @throws, a type parameter without its @param <T> tag, or a field/class without any Javadoc comment at all.

The generated sentence follows a kind-adaptive template — it is never a fixed @param … block, because the intention serves every Javadoc-able element:

  • Method parameter → @param ${var_name}

  • Method type parameter → @param <${type_param_name}>

  • Method return type → @return

  • Thrown exception type → @throws ${exception_name}

  • Field / class (prose, no tag) → ${element_name}

The shared body is:

${head} ${article} ${type_of_target} which is ${nullability_of_target}${select_start} because ${carpet_position}${select_end}.

  • ${article} is resolved from the type name's initial sound (a vs an — an Integer, a String) — never a literal a(an).

  • ${select_start} and ${select_end} are auxiliary markers describing the selection bounds, not inserted text. After generation, the region between them — the reason clause because — is selected, while the sentence's closing period stays outside it.

  • ${carpet_position} marks where the caret lands, not inserted text: the caret sits right after because , at the selection's end.

The selection is the point: a user who wants a reason simply types — the typed text replaces the selected clause, and the preserved period closes the sentence. A user who does not wants to be out in one keystroke: pressing Backspace deletes the whole because clause and leaves a complete sentence, e.g. @param key a String which is nullable..

The sentence is always English by default; other languages require an explicit opt-in in a project-level setting (Settings → Editor → Nullify), offering Always English (default) | Follow IDE language | Deutsch | Français | 日本語 | 简体中文. Javadoc targets a global developer audience, so following the IDE language by default would add noise rather than value.

Solution

When a nullability-annotated element's Javadoc does not document it yet, Alt+Enter offers Append nullability Javadoc: it appends (or creates) the Javadoc sentence

@param key a String which is nullable because <reason>.

following the kind-adaptive template — @param/@return/@throws for tag-based targets, a prose sentence for fields and classes, with the English article (a/an) chosen from the type's sound. The reason clause because is inserted selected — with the closing period left in place — and the caret right after because : type a reason to replace it in one stroke, or press Backspace to drop the clause entirely and keep a complete sentence (@param key a String which is nullable.).

The sentence is English by default; under Settings → Editor → Nullify a project-level option switches it to Follow IDE language or one of the fixed language modes (Deutsch, Français, 日本語, 简体中文).

NL-F23: Custom Javadoc Sentence Templates

Completedon version 1.0.1

Suggested on version 1.0.0 by Kurv Cygnus

Description

The Append nullability Javadoc sentence (NL-F22) is always generated from a built-in template — @param key a String which is nullable because <reason>. — no matter how the language is configured. Teams that want a different wording (a different clause order, an extra phrase, a project-specific phrasing) have no way to express it.

NL-F23 lets the user write the sentence template themselves. The doc-language option under Settings → Editor → Nullify (Edit Behavior) gains Custom...: choosing it turns the box into an editable field pre-filled with the built-in English template, and the gray comment below it swaps to an explanation of the placeholder rules. The template is expanded with the same placeholder vocabulary Append nullability Javadoc already uses:

Placeholder Meaning Optional?
${head} Tag head (@param key, @return, @throws IOException, or the field/class name) No
${type_of_target} The target's type text (String, Map<String, Integer>) No
${nullability_of_target} nullable / not null, resolved in the IDE language No
${article} a / an, resolved from the type name's initial sound Yes
${select_start} Auxiliary marker: start of the reason-clause selection, not inserted No
${select_end} Auxiliary marker: end of the reason-clause selection, not inserted; the sentence's closing period stays outside it No
${carpet_position} Auxiliary marker: the caret, not inserted; sits right after "because " at the selection's end No

${article} is the only optional placeholder. ${select_start}/${select_end} delimit the reason clause that is inserted selected (so typing a reason replaces it in one stroke, and Backspace drops the clause while keeping a complete sentence), and ${carpet_position} marks where the caret lands. A template that is blank, missing a required placeholder, contains an unknown ${...} token, or has misordered/misduplicated markers is rejected at Apply with an explanation; an invalid stored template degrades to the built-in English sentence instead of breaking the intention.

Solution

The doc-language option under Settings → Editor → Nullify (Edit Behavior) now offers Custom...: write your own sentence template for Append nullability Javadoc using ${head}, ${type_of_target}, ${nullability_of_target}, ${article}, ${select_start}, ${select_end} and ${carpet_position}. ${article} is optional; the rest are required. ${select_start}/${select_end} delimit the reason clause that is inserted selected — with the closing period staying outside it — and ${carpet_position} marks the caret right after "because ". The field pre-fills with the built-in English template; a template that is blank, missing a required placeholder, contains an unknown placeholder, or has misordered markers is rejected with an explanation, and an invalid saved template falls back to the built-in English sentence.

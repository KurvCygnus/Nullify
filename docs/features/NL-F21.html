NL-F21: CommentMaybeReasonInspection — Migrate Adjacent Comments into Nullability Annotation Reasons

Completedon version 1.0.0

Suggested on version 1.0.0 by Kurv Cygnus

Description

Developers often explain why a value is nullable or non-null in a free-floating comment next to the annotation:

// Returns null when no entry matches
@Nullable
String find(String key);

Such comments are easy to overlook — they sit outside the type system, are lost once the declaration is folded, and duplicate what the annotation itself was designed to carry. Annotations declaring a String value() member (e.g. JetBrains @NotNull/@Nullable) already provide a first-class home for exactly this sentence: @Nullable("Returns null when no entry matches"). Once migrated, the reason stays attached to the type, survives folding, and is rendered by Nullify's reason hints (NL-F16) above collapsed folds.

CommentMaybeReasonInspection detects a nullability annotation that:

  1. has a comment directly above it (same physical adjacency, no blank line or other element in between) or trailing on its right on the same line;

  2. belongs to an annotation type that supports a reason field (declares a String value() member);

  3. currently carries no valid reason value.

and offers a quick fix that migrates the comment's content into the annotation's value and removes the comment. The inspection is quick-fix only by default — it never highlights anything in the editor; the migration simply appears on Alt+Enter.

Solution

When a nullability annotation that supports a reason field (e.g. JetBrains @NotNull/@Nullable) sits directly next to a comment — on the line above it or trailing on its right — and carries no reason of its own, Nullify offers a quick fix on Alt+Enter that moves the comment's text into the annotation as its value reason and removes the comment:

// Returns null when no entry matches
@Nullable
String find(String key);

becomes

@Nullable("Returns null when no entry matches")
String find(String key);

The inspection never highlights anything by itself — it is purely a quick-fix provider. Javadoc comments and annotations without a reason field are left untouched.
